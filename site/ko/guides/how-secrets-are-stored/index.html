브라우저 확장으로 2FA 코드를 써도 안전한가: 비밀키는 어떻게 저장되나

이 글은 Popout이 각 코드의 바탕이 되는 비밀키를 어떻게 다루는지 설명합니다. 어디에 두는지, 어떻게 암호화하는지, 확장 밖으로 나가는 것이 무엇인지, 어떤 위험이 남는지입니다. 여기 적은 내용은 모두 공개된 확장 소스 코드에서 확인한 것입니다.

비밀키를 두는 곳

  • 비밀키를 포함한 모든 계정은 확장의 로컬 저장소(chrome.storage.local, 키 이름 vault)에 금고 하나로 저장됩니다. 금고는 계정마다 따로 두지 않고 암호화된 덩어리 하나입니다.
  • 금고를 풀면 그 열쇠는 확장의 세션 저장소(chrome.storage.session)에 들어 있어, 정한 자동 잠금 시간까지는 다시 묻지 않습니다. 로컬 저장소에는 쓰지 않습니다.
  • 금고의 이전 판은 변경 기록으로 브라우저의 IndexedDB(popout-authenticator)에 보관합니다. 최신 30개와 최근 30일 동안 날짜별 가장 최근 1개를 남깁니다. 잠금을 걸면 이 이전 판도 새 열쇠로 다시 암호화합니다.
  • "코드 넣기" 단추를 켠 사이트는 금고 옆에 사이트 주소 그대로 저장합니다. 비밀키는 들어 있지 않습니다.

암호화 방식

Popout은 두 겹으로 암호화합니다. 그래서 비밀번호를 바꿔도 모든 계정을 다시 암호화할 필요가 없습니다.

겹내용
금고 열쇠내 기기에서 만든 무작위 32바이트 열쇠입니다. 계정 목록 전체를 AES-256-GCM으로 암호화하며, 저장할 때마다 새 무작위 12바이트 값을 씁니다. 저장된 데이터의 SHA-256 체크섬을 함께 둡니다.
비밀번호비밀번호를 Argon2id(3회 반복, 메모리 64MiB, 병렬 1, 무작위 16바이트 솔트)로 늘려 32바이트 열쇠를 만들고, 그 열쇠로 금고 열쇠를 암호화합니다. 비밀번호는 8자 이상이어야 합니다.
복구 코드만들어 두면, 복구 코드에서 만든 열쇠(HKDF-SHA256)로 금고 열쇠의 사본을 하나 더 암호화해 둡니다.
패스키추가하면, 패스키의 PRF 출력에서 만든 열쇠(HKDF-SHA256)로 금고 열쇠의 사본을 하나 더 암호화해 둡니다. 비밀번호와 함께 씁니다.

잠금을 거는 방법과 시간은 잠금과 보호를 보세요.

잠금을 걸지 않았을 때

잠금을 걸지 않으면 금고는 여전히 AES-256-GCM으로 암호화되지만, 금고 열쇠를 같은 곳의 암호화된 데이터 바로 옆에 비밀번호 없이 저장합니다. 확장의 저장소를 읽을 수 있는 쪽은 열쇠를 읽어 계정을 풀 수 있습니다. 이 상태는 암호화되지 않은 것으로 보세요. 내 브라우저 프로필을 열 수 있는 사람에게서 비밀키를 지켜 주지 못합니다.

잠금을 걸면 달라집니다. 금고 열쇠는 암호화된 모양으로만 저장되고, 풀려면 비밀번호(또는 복구 코드)가 필요합니다. 지금 어느 상태인지는 잠금 설정에서 확인하세요.

확장 밖으로 나가는 것

  • Popout은 저장된 비밀키와 시계로 코드를 내 기기에서 만듭니다. 코드를 만들 때는 네트워크 요청을 보내지 않습니다.
  • 확장 코드에서 네트워크 요청은 선택 기능인 시계 확인 하나뿐입니다. 컴퓨터 시계가 실제 시간과 맞는지 보려고 time.akamai.com, timeapi.io, cloudflare.com에 일반 GET 요청을 보냅니다. 시계가 틀리면 코드도 틀리기 때문입니다. 요청에 계정 정보나 본문은 없습니다. 시계가 맞으면 결과를 6시간 동안, 아니면 5분 동안 다시 씁니다. 모든 웹 요청이 그렇듯 그 호스트는 내 IP 주소를 볼 수 있습니다. 기본으로 켜져 있고 설정에서 끌 수 있습니다.
  • 확장에는 분석·사용 통계·계정 로그인·개발자가 운영하는 서버가 없습니다.

브라우저 동기화

  • 동기화를 켜면 Popout은 계정을 하나씩 AES-256-GCM으로 암호화해 브라우저 자체의 동기화 저장소(chrome.storage.sync)에 씁니다. 기기 사이로 옮기는 일은 브라우저 회사의 동기화 서비스가 합니다. Popout이 동기화 서버를 운영하지는 않습니다.
  • 기본은 잠금을 건 뒤에만 동기화합니다. 잠금 없이 동기화하려면 "잠금 없이 동기화 허용"을 따로 골라야 합니다. 잠금이 없으면 금고 열쇠가 평문으로 저장되므로(위 참고) 이 설정을 켜면 동기화된 데이터에 접근할 수 있는 누구나 읽을 수 있는 계정이 올라갑니다. 파이어폭스 판은 동기화를 켤 때 데이터 수집 권한도 묻습니다.
  • 사파리 판에는 기기 사이 동기화가 없습니다.
  • 단계는 백업·내보내기·동기화를 보세요.

요청하는 권한

확장 manifest에 적힌 권한입니다. 이유는 프로젝트 README에 적힌 것과 같습니다.

권한이유
storage, unlimitedStorage금고·설정·변경 기록을 기기에 둡니다. 뒤의 것은 그 기록이 기본 저장 한도에 걸리지 않게 합니다.
activeTab, scripting현재 탭에 코드를 넣고 그 탭의 QR을 읽습니다. 클릭·오른쪽 클릭·단축키를 누른 뒤에만 합니다.
alarms자동 잠금, 주기적 동기화, 클립보드 지우기, 정리 타이머.
contextMenus입력칸의 "2FA 코드 넣기"와 도구 모음 아이콘의 "별도 창에서 열기" 항목.
clipboardWrite코드·공유 링크·복구 코드를 복사합니다.
offscreen, sidePanel (크롬·엣지)복사한 코드를 정한 시간 뒤 클립보드에서 지우고, 사이드 패널을 엽니다.
tabs, clipboardRead (선택)필요할 때만 요청합니다. 앞의 것은 별도 창·사이드 패널이 지금 탭의 사이트에 맞는 계정을 추천하게 하고, 뒤의 것은 클립보드 지우기를 켤 때만 요청합니다.
사이트 접근: https://*/*, localhost, 127.0.0.1 (선택)설치할 때 허용되지 않습니다. 관련된 사이트에 대해서만 묻습니다. 별도 창·사이드 패널에서 넣을 때의 현재 사이트, "코드 넣기" 단추에 적은 사이트, 자동 인식을 켠 경우 정해진 서비스 목록입니다. 모든 사이트를 한꺼번에 요청하지 않습니다.

manifest에는 설치할 때 허용되는 사이트 접근이 없습니다. 모두 선택 권한이며 위 표의 마지막 줄처럼 나중에 요청합니다.

백업과 공유 링크

  • 일반 백업 파일은 그대로 읽힙니다. 비밀키가 평문으로 들어 있으니 비밀번호처럼 보관하거나, 정한 비밀번호로 Argon2id와 AES-GCM을 쓰는 암호화 백업을 고르세요.
  • 공유 링크에는 앞으로의 코드만 들어 있고 비밀키는 없습니다. 링크는 내 기기에서 만들며, 데이터는 주소의 # 뒤에 있어 브라우저가 페이지 서버로 보내지 않습니다. 비밀번호 없는 링크는 링크를 가진 누구나 열 수 있습니다. 비밀번호를 건 링크는 그 비밀번호에서 만든 열쇠(PBKDF2-SHA256, 600,000회)로 암호화합니다. 링크로 코드 공유를 보세요.

막지 못하는 것

데이터가 놓이는 자리 때문에 생기는 한계이고, 어떤 설정으로도 없어지지 않습니다.

  • 내 계정으로 도는 악성 프로그램. 같은 브라우저 프로필에서 나로서 실행되는 것은 확장이 읽을 수 있는 것을 읽을 수 있고, 잠금이 풀린 상태도 지켜볼 수 있습니다. 잠금은 금고가 잠겨 있는 동안만 도움이 됩니다.
  • 잠금이 없고 파일에 접근할 수 있을 때. 잠금이 없으면 브라우저 프로필 폴더를 복사할 수 있는 사람이 위에서 설명한 대로 계정을 읽을 수 있습니다.
  • 남의 손에 들어간 백업 파일. 일반 백업은 가진 사람이 그대로 쓸 수 있습니다. 어디에 두는지는 본인 몫입니다.
  • 복사한 코드. 복사한 코드는 다른 프로그램도 읽을 수 있는 시스템 클립보드에 남습니다. 클립보드 자동 지우기는 기본으로 꺼져 있고, 켤 수 있습니다.
  • 약하거나 다른 곳에서도 쓰는 비밀번호. Argon2id가 추측을 늦추지만 짧거나 흔한 비밀번호를 강하게 만들지는 못합니다.
  • 엉뚱한 사이트에 넣는 일. Popout은 코드를 넣기 전에 페이지 주소를 확인하고 사이트가 일치하지 않으면 묻지만(사이트 일치 확인), 물을 때 결정은 본인이 합니다.

휴대폰 앱은 데이터를 브라우저 밖, 다른 기기에 둡니다. 브라우저 확장은 지금 쓰는 컴퓨터의 브라우저 프로필 안에 둡니다. 위험이 서로 다르고, 이 글은 Popout만 설명합니다.

직접 확인하기

확장의 소스 코드는 MIT 라이선스로 github.com/elitekid/popout-authenticator에 공개되어 있습니다. manifest에 위의 권한이 적혀 있고, 개인정보처리방침도 같은 네트워크 사용을 설명합니다. 이 글에서 코드와 다른 부분을 찾으면 프로젝트 이슈로 알려 주세요.

평가 남기기 쓰는 브라우저의 스토어에 남긴 짧은 평가가 다른 사람이 Popout을 찾는 데 도움이 됩니다.
