문제 해결

코드가 맞지 않을 때, 코드 넣기가 안 될 때, 잠금이 풀리지 않을 때, 가져오기가 안 될 때 확인할 것.

  1. 사이트가 코드를 거절할 때
  2. 코드가 넣어지지 않을 때
  3. 단축키가 작동하지 않을 때
  4. 잠금을 풀 수 없을 때
  5. 가져오기 오류
  6. 사이드 패널이 보이지 않을 때
  7. 동기화가 보이지 않을 때
  8. 금고를 읽지 못할 때
  9. 문제 알리기

사이트가 코드를 거절할 때

아래 순서대로 확인하세요.

1. 시계 확인

코드는 시간에 따라 만들어집니다. 컴퓨터 시계가 1분 넘게 어긋나면 사이트가 모든 코드를 거절할 수 있습니다.

  1. 설정 → "시계 확인"을 엽니다. "인증 도구를 열 때 인터넷 시간과 비교하기"가 켜져 있는지 보고 "지금 확인"을 누릅니다.
  2. 결과를 읽습니다. "기기 시간이 맞습니다. (차이 N초)"면 정상입니다. "기기 시간과 N초 차이가 있습니다."면 어긋난 것입니다. 작은 차이는 자동으로 반영합니다("시간 차이를 반영해 인증 코드를 만듭니다."). 차이가 크면 "차이가 너무 커서 보정할 수 없습니다. 기기의 날짜와 시간 설정을 확인해 주세요."가 나옵니다.
  3. 이때는 운영체제의 날짜·시간 자동 설정을 켠 뒤 다시 시도하세요.

이 확인은 time.akamai.com, timeapi.io, cloudflare.com에 현재 시각만 묻습니다. 요청에 계정 정보는 들어가지 않으며, 해당 서비스는 IP 주소를 볼 수 있습니다. 확인을 끄면 기기 시간을 그대로 씁니다("시계 확인이 꺼져 있습니다. 기기 시간을 그대로 사용합니다."). 서버에 닿지 못하면 "시간을 확인하지 못했습니다. 기기 시간을 그대로 사용합니다."가 나옵니다.

2. 계정 설정 확인

시계가 맞아도 계정을 서비스와 다른 설정으로 저장했다면 코드가 다릅니다. 인증 방식, 알고리즘, 코드 자릿수, 갱신 주기(초)를 서비스가 등록 때 보여 준 값과 비교하세요. 방금 추가한 계정이라면 "코드가 맞지 않나요?" → "설정 확인"을 열고 휴대폰 인증 앱의 코드와 비교해, 같은 코드가 나오는 조합("SHA-1 · 6자리" 같은 형태)을 고르세요. 시작하기도 참고하세요.

3. 새 코드 쓰기

새 코드가 나올 때까지 기다리거나, 코드가 곧 바뀔 때는 "다음 코드 복사"를 쓰세요.

코드가 넣어지지 않을 때

Popout은 확인할 수 있는 페이지에만 코드를 넣습니다. 전체 방법은 로그인 화면에 코드 넣기를 보세요. 흔한 원인은 다음과 같습니다.

  • 사이트 접근 권한이 없음. "이 사이트에 입력할 권한이 없습니다. 사이트 접근을 허용하거나, 대상 사이트의 브라우저 툴바에서 확장을 열고 다시 눌러 주세요."가 나옵니다. 권한 창에서 "example.com에서 넣기 허용"(해당 사이트 주소로 표시)을 누르세요.
  • https가 아닌 페이지. "보안 연결(https)이 아닌 페이지에는 코드를 넣지 않습니다." localhost와 127.0.0.1은 예외입니다.
  • 다른 사이트의 프레임 안에 입력칸이 있음. 그 프레임의 주소도 보안 연결이어야 하고 계정에 지정한 사이트여야 합니다. 아니면 "이 계정에 지정한 사이트가 아닙니다. 주소를 확인한 뒤 다시 눌러 주세요."가 나옵니다. 주소가 맞다면 "이번만 넣기"나 "기억하고 넣기"를 고르세요.
  • 금고가 잠김. "금고가 잠겼습니다. 잠금을 해제한 뒤 다시 눌러 주세요."
  • 코드를 넣을 수 없는 페이지(브라우저 내부 페이지 등): "이 페이지에는 코드를 넣을 수 없습니다. 인증할 사이트에서 다시 눌러 주세요."
  • 입력칸을 찾지 못함. 이때는 코드를 복사해 줍니다. "입력칸을 찾지 못해 코드를 복사했습니다. 사이트에 붙여넣어 주세요." 코드 입력칸을 한 번 누르고 다시 시도하거나, 직접 붙여 넣으세요.

1.0.1 1.0.1부터 코드 칸이라는 단서가 없는 전화번호 칸은 고르지 않습니다. 그런 페이지에서 코드가 넣어지지 않으면 실제 코드 입력칸을 눌러 다시 시도하거나 코드를 복사해서 붙여 넣으세요.

단축키가 작동하지 않을 때

코드 넣기 단축키는 Ctrl+Shift+Y(맥은 Command+Shift+Y)입니다. 그 밖의 동작(화면의 QR 코드 읽기, 사이트에 맞는 계정의 코드 넣기, 코드 가리기·보이기, 별도 창으로 열기)에는 기본 키가 없습니다.

  1. 브라우저의 확장 프로그램 단축키 설정 화면을 엽니다.
  2. 팝업 인증 도구를 찾아 동작마다 키를 지정하거나 바꿉니다.
  3. 다른 확장이나 브라우저가 같은 키를 쓰고 있으면 다른 조합을 고르세요.
  4. 키를 누르기 전에 코드 입력칸에 커서를 두세요. 그래도 안 되면 코드가 넣어지지 않을 때를 확인하세요.

단축키 없이 우클릭 메뉴의 "인증 코드 넣기"를 써도 같은 동작을 합니다.

잠금을 풀 수 없을 때

  • "비밀번호가 맞지 않습니다." 자판 언어와 Caps Lock을 확인하세요.
  • "복구 코드로 잠금 해제"를 누르고 복구 코드를 입력하세요. "복구 코드가 맞지 않습니다."는 오타이거나 이미 새 코드로 바뀐 옛 코드일 때 나옵니다.
  • "패스키로 잠금 해제"도 쓸 수 있습니다. Firefox에서는 패스키를 쓸 수 없습니다.

비밀번호와 복구 코드를 잃었다면 등록한 패스키로 풀어 보세요. 셋 다 쓸 수 없다면 금고를 열 수 없습니다. 비밀번호를 잊었다면을 보세요.

가져오기 오류

파일, 링크, QR 이미지로 계정을 추가할 때 볼 수 있는 안내입니다. 앱별 방법은 다른 앱에서 옮기기를 보세요.

안내뜻해결
"알 수 없는 형식입니다."인식하지 못하는 백업 파일입니다.지원하는 형식으로 앱에서 다시 내보내세요.
"Aegis 앱에서 암호화 없이 내보낸 파일을 써 주세요."암호화된 내보내기 파일입니다(앱 이름은 Aegis, 2FAS, Bitwarden 중 하나로 바뀝니다).그 앱에서 암호화 없이 내보낸 파일을 쓰세요.
"암호화된 백업입니다. 비밀번호를 입력해 주세요." / "비밀번호가 맞지 않습니다."백업에 비밀번호가 필요하거나 입력한 비밀번호가 틀렸습니다."백업 비밀번호"에 입력하고 "확인"을 누르세요.
"파일을 읽지 못했습니다."고른 파일을 열지 못했습니다.파일을 다시 고르거나 새로 내보내세요.
"링크를 읽지 못했습니다."붙여 넣은 링크가 올바른 otpauth:// 링크가 아닙니다.링크를 한 줄에 하나씩, 끝까지 붙여 넣으세요.
"링크는 한 번에 500개까지만 가져왔습니다. 나머지는 다시 넣어 주세요."한 번에 500개까지 읽습니다.남은 링크를 한 번 더 붙여 넣으세요.
"비밀키 형식이 맞지 않습니다."입력한 비밀키를 읽을 수 없습니다.서비스에서 다시 복사하세요. 다른 문자가 섞이지 않게 합니다.
"자릿수는 6~10 사이 정수여야 합니다." / "주기는 1~3600초 사이 정수여야 합니다."직접 입력한 값이 범위를 벗어났습니다.서비스가 보여 준 값을 쓰세요.
"QR 코드를 찾지 못했습니다." / "인증 계정을 추가하는 QR 코드가 아닙니다." / "이미지를 읽지 못했습니다."이미지에서 읽을 수 있는 인증 QR 코드가 없습니다.QR 코드 전체가 크고 선명하게 나온 이미지를 쓰세요.
"원시 사본 파일이 아닙니다." / "사본을 열지 못했습니다."원시 사본이 아니거나 비밀번호가 맞지 않습니다.파일과 사본의 비밀번호를 확인하세요.

사이드 패널이 보이지 않을 때

설정 → "화면" → "여는 방식"을 엽니다. "사이드 패널"은 브라우저가 사이드 패널을 제공할 때만 목록에 나옵니다. Safari에서는 저장해 둔 "사이드 패널"이 "팝업"으로 바뀝니다. 대신 "팝업"이나 "별도 창"을 고르세요.

동기화가 보이지 않을 때

설정 → "동기화"를 엽니다. 상태 문구가 이유를 알려 줍니다.

  • "동기화가 꺼져 있습니다." "같은 브라우저 계정으로 로그인한 기기와 동기화"를 켜세요.
  • "계정을 암호화해 동기화하려면 잠금을 설정해 주세요." 잠금을 켜거나 "잠금 없이 동기화 허용"을 켜세요(이때 비밀키가 암호화되지 않은 채 전송됩니다).
  • "잠겨 있어서 동기화하지 못했습니다. 잠금을 해제해 주세요."
  • "다른 기기에서 동기화한 계정이 있습니다. 해당 기기에서 설정한 금고 비밀번호로 계정을 합쳐 주세요."
  • "브라우저의 동기화 저장 공간이 부족합니다." 또는 "다른 기기의 데이터를 확인하고 있습니다. 잠시 뒤 다시 시도해 주세요."

"지금 동기화"를 눌러 다시 시도하세요. Firefox는 먼저 허용을 요청합니다("Firefox 동기화로 암호화된 계정을 보내려면 허용이 필요합니다."). Safari에서는 "이 브라우저는 기기 간 동기화를 지원하지 않습니다. 다른 기기로 옮길 때 백업 파일을 사용해 주세요."라고 나옵니다. 두 기기 모두 같은 브라우저 계정에 로그인해 있어야 합니다. 자세한 내용은 백업·내보내기·동기화를 보세요.

금고를 읽지 못할 때

"계정 데이터를 읽지 못했습니다. 초기화하거나 확장을 삭제하지 말고 아래 복구 방법을 확인해 주세요."가 나오면 "백업"을 엽니다.

  1. 먼저 "원시 사본 저장"을 눌러 지금 상태를 보관합니다.
  2. "스냅샷 복원"에서 이전 스냅샷을 고릅니다. 1.0.0에서는 현재 금고가 손상된 동안 "없는 계정만 추가"가 실패할 수 있습니다. "목록 전체 복원"은 현재 목록을 스냅샷의 목록으로 바꿉니다.
  3. 1.0.0의 "원시 사본에서 가져오기"는 현재 금고를 읽을 수 있을 때만 됩니다.

1.0.1 1.0.1부터는 현재 금고가 손상됐어도 원시 사본을 가져올 수 있습니다.

확장을 삭제하면 계정·스냅샷도 함께 삭제됩니다. 먼저 백업 파일을 저장해 두세요.

문제 알리기

github.com/elitekid/popout-authenticator/issues에 이슈를 남겨 주세요. 브라우저 이름과 버전, 확장 버전(설정의 "버전"), 한 동작, 나타난 안내 문구를 함께 적어 주세요. 비밀키, 복구 코드, 인증 코드는 올리지 마세요.

평가 남기기 쓰는 브라우저의 스토어에 남긴 짧은 평가가 다른 사람이 Popout을 찾는 데 도움이 됩니다.
