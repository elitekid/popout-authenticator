사이트 일치 확인: 지정한 주소에만 넣기

Popout은 지금 보는 페이지를 계정에 저장한 사이트 주소와 비교합니다. 코드가 비슷하게 생긴 주소로 저절로 넘어가는 일을 줄이는 데 도움이 됩니다.

  1. 무엇을 비교하나
  2. 어떤 경우가 일치인가
  3. 사이트가 일치하지 않을 때
  4. 계정을 대신 고르는 경우
  5. 보안 연결 페이지에서만
  6. 피할 습관

무엇을 비교하나

계정마다 "사이트 주소"를 지정할 수 있습니다. 예: example.com. 코드를 넣을 때 Popout은 코드 칸이 있는 페이지의 주소를 그 계정에 저장한 주소와 비교합니다. 내가 지정한 주소와 비교하므로, 페이지가 어떻게 생겼는지나 이름이 무엇인지에 따라 결과가 달라지지 않습니다.

주소를 추가하려면 계정의 "⋯" 메뉴 → "편집"에서 "사이트 주소 (쉼표 또는 줄바꿈으로 구분)" 칸에 입력하세요. 코드를 넣는 방법은 로그인 화면에 코드 넣기를 보세요.

어떤 경우가 일치인가

페이지의 호스트가 저장한 주소와 같거나, 그 주소의 하위 도메인일 때만 일치로 봅니다.

저장한 주소페이지 호스트일치
example.comexample.com예
example.comlogin.example.com예, 하위 도메인
login.example.comexample.com아니요
example.comexample.com.other.test아니요

Popout은 주소를 기본 도메인 단위로 묶지 않습니다. github.io처럼 하위 도메인마다 주인이 다른 도메인이 있어서, 기본 도메인이 같다는 사실만으로는 누가 운영하는 페이지인지 알 수 없기 때문입니다.

코드 칸 옆 "코드 넣기" 단추를 켜 둔 사이트도 그 계정의 저장한 사이트로 칩니다.

확인은 탭의 주소만 보지 않고 코드 칸이 실제로 있는 문서의 주소로 합니다. 페이지 안의 프레임은 그 프레임 자체의 주소로 확인합니다.

사이트가 일치하지 않을 때

페이지가 그 계정에 저장한 사이트가 아니면 Popout은 코드를 넣지 않고 먼저 팝업에서 묻습니다. 찾은 호스트와 "주소를 확인한 뒤 넣어 주세요."라는 안내가 함께 보입니다. 이렇게 고릅니다.

  • "기억하고 넣기": 이 호스트를 이 계정의 사이트 주소로 저장한 뒤 넣습니다. 다음부터 그곳에서는 일치로 처리됩니다.
  • "이번만 넣기": 지금 넣기만 하고 저장하지 않습니다. 자동 제출이 켜져 있어도 제출하지 않습니다.
  • "취소": 아무것도 넣지 않습니다.

고르기 전에 브라우저 주소 표시줄의 주소를 확인하세요.

계정을 대신 고르는 경우

단축키, 오른쪽 클릭 메뉴, 팝업에서 강조된 계정은 Popout이 계정을 대신 고릅니다. 이때는 저장한 사이트가 페이지와 일치하는 계정만 고릅니다. 이름이 비슷한지, 얼마나 자주 썼는지는 쓰지 않습니다.

팝업의 추천 목록에는 이름이 비슷한 계정이 함께 보일 수 있습니다. 눈에 보이는 후보일 뿐이고 직접 골라야 합니다. 그 계정에 저장하지 않은 사이트에서 그 후보로 넣으려 하면 위의 질문이 나옵니다.

보안 연결 페이지에서만

  • Popout은 https 페이지에서만 코드를 넣습니다. 로컬 시험 주소 localhost와 127.0.0.1은 http도 허용합니다.
  • 맨 위 페이지의 주소와, 코드를 넣을 문서의 주소를 둘 다 확인합니다. 맨 위 페이지가 안전해도 다른 사이트의 프레임에는 넣지 않습니다.
  • about:blank 같은 프레임은 거절합니다.

피할 습관

습관처럼 "기억하고 넣기"를 누르면 이 확인의 보호가 약해집니다. 비슷하게 생긴 주소가 저장한 사이트가 되기 때문입니다. 주소 표시줄의 주소가 내가 뜻한 주소일 때만 누르세요.

평가 남기기 쓰는 브라우저의 스토어에 남긴 짧은 평가가 다른 사람이 Popout을 찾는 데 도움이 됩니다.
