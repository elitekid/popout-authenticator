IT admin deployment guide

This page is for administrators at a company or school who have deployed the original Authenticator extension (authenticator.cc) with managed policy, or plan to. Popout Authenticator reads the same policy key names. Check the table below for how each key behaves before you reuse existing values.

Policy keys

Popout reads these eight keys from the browser's managed storage (declared in managed_schema.json). The key names match the original extension's schema. The original's disableInstallHelp key is not accepted.

KeyTypeWhat it does
storageAreastring: sync or localForces browser sync on (sync) or off (local). The main store stays local either way. The sync setting is locked for the user. Any other value is ignored.
disableBackupbooleanRead and accepted, but the current code does not use it to hide anything yet.
disableExportbooleanWhen true, the backup page shows a notice instead of the export option, the raw copy save is hidden, and the per-account export in the popup is hidden.
enforcePasswordbooleanWhen true, users who have no password lock are asked to set one. Adding accounts and importing a raw copy are held back until the lock is on, and the user cannot turn the lock off.
enforceAutolocknumber (minutes)Sets the auto-lock time and locks that setting for the user. Values of 0 or below are ignored; values above 1440 (24 hours) are capped at 1440.
passwordPolicystring (regular expression)A new password must match this expression. An empty value or an invalid expression is ignored.
passwordPolicyHintstringText shown when a password does not match passwordPolicy.
feedbackURLstring (http or https URL)Replaces the address of the feedback link in Settings. Other schemes and invalid URLs are ignored.

Popout reads the policy once per page and reads it again when the policy changes. If the read takes more than one second or fails, it is treated as "no policy" for that read.

There is no policy for putting secret keys into an extension policy to roll out accounts in bulk.

Passing policy values

The values below are made-up examples. Replace <ID> with the extension ID for your browser.

Windows registry (Chrome)

Create a policy key under the path below, then add one value per policy key (strings as REG_SZ, numbers and booleans as REG_DWORD).

HKLM\Software\Policies\Google\Chrome\3rdparty\extensions\<ID>\policy

macOS (Chrome)

Use a property list whose name is com.google.Chrome.extensions.<ID>:

<?xml version="1.0" encoding="UTF-8"?>
<plist version="1.0">
<dict>
  <key>enforcePassword</key>
  <true/>
  <key>enforceAutolock</key>
  <integer>15</integer>
  <key>passwordPolicy</key>
  <string>^.{12,}$</string>
</dict>
</plist>

Firefox (policies.json)

Popout's Firefox build declares the same managed schema and reads it through storage.managed.

{
  "policies": {
    "3rdparty": {
      "Extensions": {
        "popout-authenticator@elitekid": {
          "enforcePassword": true,
          "enforceAutolock": 15,
          "passwordPolicy": "^.{12,}$",
          "passwordPolicyHint": "Use at least 12 characters."
        }
      }
    }
  }
}
